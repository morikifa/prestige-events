## 2. Входные и выходные данные

| Требование | Реализация |
| --- | --- |
| Данные вводятся через браузер, передача HTTP/HTTPS | формы и POST-запросы в `public/index.php` |

| Выход — страницы браузера | серверный рендеринг шаблонов из `app/views` |

| Уведомления | таблица `notifications`, личный кабинет |

## 3. Временные характеристики и надёжность

- страницы отдаются серверным рендерингом, объём данных ограничен индексами;
- проверка входных данных выполняется на клиенте (обязательные поля, типы `input`)
  и обязательно на сервере (валидация в `app/pages/*`);
- при некорректных данных сохранение не выполняется и выводится сообщение;
- дубли записей исключены уникальными ключами `(event_id, user_id)`;
- резервное копирование — раздел «Резервные копии» и `tools/backup-cron.php`;
- при сбое базы выводится страница с диагностикой, данные не теряются.

## 4. Программная совместимость и защита

| Требование | Реализация |
| --- | --- |
| PHP 8.1+, MySQL, HTML5/CSS3, JavaScript | проект без фреймворков, ES5-совместимый скрипт интерфейса |
| Подготовленные запросы | все обращения идут через PDO `prepare/execute` |
| Защита от XSS | экранирование вывода функцией `e()` |
| Защита от CSRF | токен в каждой форме, проверка `csrf_verify()` |

| HTTPS | настраивается на веб-сервере, cookie с `SameSite` и признаком `secure` при HTTPS |
| Адаптивный русифицированный интерфейс | единая таблица стилей с медиазапросами, весь текст на русском |
| Обработка персональных данных (152-ФЗ) | согласие при регистрации, минимальный набор полей |

## 5. Отличия от буквы ТЗ

1. СУБД: в ТЗ указан Microsoft SQL Server, в проекте — MySQL/MariaDB. Причина и порядок
   переноса описаны в `docs/02-baza-dannyh.md`, структура таблиц сохранена.
2. Восстановление пароля: в учебном проекте нет почтового сервера, поэтому смена пароля
   выполняется в личном кабинете после ввода текущего пароля. Для реальной рассылки
   писем достаточно подключить SMTP.
3. Уведомления по электронной почте: таблица хранит канал (`email` или `web`), отправка
   выполняется внутри платформы. Подключение SMTP-транспорта — отдельная задача эксплуатации.
4. Цветовое оформление и типографика выбраны по заданному образцу: тёмная и светлая темы,
   крупные геометрические заголовки, два основных цвета и один акцентный.

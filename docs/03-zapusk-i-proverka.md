# Запуск и проверка работоспособности

## 1. Чек-лист запуска

1. MySQL запущен, база `prestige_events` создана.
2. В `app/config.php` верные логин и пароль базы.
3. В корне проекта выполнена команда:

```bash
php -S localhost:8000 -t public
```

4. Открыт адрес <http://localhost:8000>.
5. На странице видна афиша, фильтры и список мероприятий.
6. Вход выполняется под учётной записью нужной роли.
7. Разделы другой роли недоступны: при попытке открыть адрес вручную появляется
   страница «Доступ запрещён».

## 3. Проверка разграничения доступа

Выполните по очереди под разными ролями. Все проверки должны давать отказ.

1. Участник открывает `http://localhost:8000/index.php?r=admin/users` — «Доступ запрещён».
2. Организатор открывает `?r=admin/settings` — «Доступ запрещён».
3. Организатор открывает участников чужого мероприятия `?r=manage/participants&id=2` — «Доступ запрещён».
4. Гость открывает `?r=account` — перенаправление на форму входа.
5. В профиле участника отсутствует поле «Роль»; при попытке отправить лишнее поле
   в запросе роль не меняется (сервер не читает это поле).
6. Организатор не может отметить посещение по токену чужого мероприятия.

## 4. Проверка защиты

1. **CSRF.** Откройте страницу с формой, удалите в браузере скрытое поле `_token`
   (инструменты разработчика) и отправьте форму. Действие не выполнится, появится
   сообщение об устаревшей сессии.
2. **SQL-инъекция.** В поле поиска введите `' OR 1=1 --`. Результат — обычный поиск без
   записей, ошибок SQL нет: запросы параметризованы.
3. **XSS.** В названии мероприятия сохраните текст `<script>alert(1)</script>`.
   На странице он отображается как текст, скрипт не выполняется.
4. **Пароли.** В базе поле `password_hash` содержит строку `$2y$10$...` — хеш bcrypt.
5. **Блокировка перебора.** Пять раз введите неверный пароль: вход временно блокируется
   на 10 минут (сообщение с оставшимся временем).
6. **Сессия.** После выхода кнопка «Назад» в браузере не открывает закрытые страницы.

## 5. Типовые ошибки и решения

| Сообщение | Причина | Решение |
| --- | --- | --- |
| «Нет подключения к базе данных» | MySQL выключен или неверные параметры | запустите MySQL, проверьте `app/config.php` |
| `SQLSTATE[HY000] [1049] Unknown database` | не импортирована схема | выполните `database/schema.sql` |
| `could not find driver` | нет `pdo_mysql` | включите расширение в `php.ini` |
| «Ошибка базы данных: no such table» в демо-режиме | не собрана демо-база | `php tools/demo-db.php` |
| «Ключ: латиница, цифры…» в настройках | ключ параметра с кириллицей | используйте латиницу и подчёркивание |
| Не создаётся резервная копия | нет прав на запись в `storage/backups` | выдайте права на каталог |
| Пустая страница после входа | ошибка PHP скрыта | включите `'debug' => true` в `app/config.php` и повторите |

## 6. Сброс данных к исходному состоянию

```bash
mysql -u root -p < database/schema.sql
mysql -u root -p < database/seed.sql
```

или для демо-режима:

```bash
php tools/demo-db.php
```

## 7. Запуск под Apache или Nginx

**Apache (XAMPP).** Скопируйте проект в `htdocs`, откройте
`http://localhost/prestige-events/public/`. В `.htaccess` уже отключён просмотр каталогов.

**Nginx.** Пример блока сервера:

```nginx
server {
    listen 80;
    server_name prestige.local;
    root /var/www/prestige-events/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    }
}
```

Для работы по HTTPS настройте сертификат (Let's Encrypt или самоподписанный) и
раскомментируйте проверку `secure` в `app/bootstrap.php`.
